## What Changed This Session

### Phase 2 production bug — three sub-issues all fixed

**Symptom:** Maps voted via in-game vote failed with `E datafile: failed to open file 'maps/<MapName>.map'`. Confirmed via user's DDNet server log.

**Root causes (in order of discovery):**

1. **`storage.cfg` had wrong shape.** Initially installed a single line `add_path $USERDIR/types`, but DDNet's `CServer::LoadMap` unconditionally prepends `maps/` to the map name. `types/maps/Pokakal.map` doesn't exist; only `types/<category>/maps/Pokakal.map` does. Fixed by emitting per-category add_paths matching upstream's `storage.cfg` layout.

2. **Testingmaps were laid out wrong.** `sync_testing_maps` wrote `.map` files directly to `types/testingmaps/*.map` (no `maps/` subfolder). DDNet couldn't resolve them under any add_path. Fixed: now writes to `types/testingmaps/maps/*.map`. Added `_migrate_testingmaps_layout()` for one-time migration of existing installs.

3. **`record_maps.Server` column was wrong.** Inserts used `Server=<category>` (e.g. `'novice'`, `'testing'`). DDNet's convention (per upstream `add_maps.ps1`) is `Server='DDNet'` for every row — the server's vote/scoring matches on (Map, Server). Wrong values broke `sv_map` lookups. Fixed: hardcoded `Server='DDNet'`. Added `repair_server_column` opt-in CLI flag that updates only rows whose `Map` matches a currently-synced stem (so user-added entries are never touched).

**Then a deeper layer:** the user's DDNet server runs from a Steam install (`E:\SteamLibrary\...\ddnet`), not from `%APPDATA%\DDNet`. DDNet's storage subsystem reads `storage.cfg` from `$CURRENTDIR` — the directory the binary was launched from. We were writing to the wrong file entirely. Two more fixes:

4. **`$USERDIR` is NOT expanded as a prefix.** Confirmed by reading upstream `src/engine/shared/storage.cpp` `AddPath()`: it uses `str_comp` (exact-match) for the three magic tokens. `add_path $USERDIR/types/oldschool` fails with `cannot add path which is not a directory` because the server treats the literal string as a path. Fixed: emit absolute paths instead.

5. **Resolver for the install directory.** `web/server.py::_resolve_server_storage_cfg()` now finds the right `storage.cfg`:
   - Honors `DDNETCONTROL_STORAGE_CFG` env override
   - Probes running `DDNet-Server.exe` via WMIC and uses its directory
   - Falls back to picking the newest Steam install (by `DDNet-Server.exe` mtime) across drive letters
   - Threads the resolved path through `sync_ddnet_maps` → `register_with_server` → `ensure_storage_cfg`

### Feature — combined `types/_all/` directory

**Why:** DDNet's `MAX_PATHS = 16` is a hard cap. With three base slots (`$USERDIR`/`$DATADIR`/`$CURRENTDIR`) reserved, only 13 category add_paths fit, so categories like `fun` and `event` were dropped on every boot.

**How:** `rebuild_combined_maps_dir()` creates `%APPDATA%\DDNet\types\_all\maps\` and hardlinks every `.map` from every category into it. Hardlinks are zero-cost (same inode, no extra disk space). On copy fallback (different volume, etc.) it falls back to `shutil.copy2`. Idempotent: existing inode-matched links are skipped, stale entries removed, deduped by stem with stable alphabetical ordering.

**Result:** `storage.cfg` now has just one category line: `add_path C:/Users/rust-/AppData/Roaming/DDNet/types/_all`. **4261 maps** in maplist (was 4212 with per-category, 49 more coverage). Live tested — `Somewhere in the Sky` (oldschool), `Pokakal`/`Mitosis` (testingmaps), `2 Days in the back` (event), `8bit Full Adder` (fun) all load via econ change_map without datafile errors.

## Hard Constraints from User (Reaffirmed)

1. **NEVER write to `%APPDATA%\DDNet\maps\`.** User's personal uploaded maps live there. Any write — copy, move, overwrite — is forbidden. This is why we hardlink into `types/_all/maps/` instead.

2. **NEVER DELETE or UPDATE `record_maps` rows.** Only `INSERT OR IGNORE`. The opt-in `--repair-server-column` flag is the one exception, and it only touches rows whose `Map` stem matches a currently-synced map (so user-added rows are never altered).

3. **NEVER touch other DB tables.** `record_race`, `record_teamrace`, `record_saves`, `record_points`, and their `_backup` siblings are off-limits. `ddnet-cache.sqlite3` is also off-limits entirely.

4. **All UI-touching changes MUST go through Chrome DevTools MCP end-to-end** (steering rule). Port-bind benchmarks alone are insufficient.

5. **Python 3.13+ on PATH.** `pythonw.exe` is 3.14 at `C:\Python314\pythonw.exe`. No `cgi` module, stricter stdio handling under pythonw (we sink stdout/stderr to devnull when console streams are absent).

6. **Hostname `rust` has no reverse DNS.** `socket.getfqdn()` blocks 12+ s. Already worked around via `FastHTTPServer` subclass; anywhere else DNS could sneak in needs to be handled.
